# 角色工作台与学生数据范围

## 角色矩阵

| 角色 | 默认学生范围 | 学生资料修改 | 家庭联系人修改 |
| --- | --- | --- | --- |
| 总管理员 | 全校 | 可以 | 可以 |
| 管理员 | 全校 | 可以 | 可以 |
| 学工老师 `student_affairs` | 全校 | 不可以 | 不可以 |
| 辅导员 | 账号所属分院全部学生 | 不可以 | 仅所属分院 |
| 普通人员 | 无 | 不可以 | 不可以 |

有效人员例外授权与角色默认查看范围取并集，可添加指定分院或全校的只读范围，不增加修改权限。带班管理授权与学生查看权限分离；跨分院带班关系本身不授予跨分院查看权限。辅导员缺失所属分院代码时，不授予默认学生范围，首页提示联系管理员。

## 管理员配置方法

1. 总管理员进入“人员与权限”，选择在职教职工并设置系统角色。学工人员选择“学工老师”，辅导员选择“辅导员”。
2. 辅导员范围通过账号 `dwbm` 与学生 `dwbm` 精确匹配。账号分院来自既有教职工目录/登录资料；需确认分院代码正确。
3. 需要额外查看其他分院的人员，在“学生权限清单”中添加或启用人员授权；撤销授权后，额外范围在下一次请求失效。
4. 带班关系的维护权限仍通过已有带班管理授权配置，不自动增加学生或家庭资料的写权限。
5. 登录与在职人员同步保留已分配角色；原有离职停用机制继续撤销权限，不自动恢复。

新增角色不自动分配给现有账号，不按“学工”文字或单位代码推断。普通管理员仍不能分配角色或查看登录日志；导入、同步、学生权限清单和 Snippets 限管理员。CAS 关闭时保留原有本地开发模式，权限隔离以 CAS 启用环境为准。

## 实现与兼容

- `StudentAccess` 集中处理角色默认范围、有效人员授权、查询范围、单个学生查看及修改能力；学生列表、毕业生、筛选和统计使用相同范围。
- 家庭列表与详情按关联学生过滤，宿舍成员/统计、详情中的随行人员也过滤范围外学生。范围内家庭列表响应新增 `can_update` 布尔值供前端逐行控制编辑按钮。
- `WorkspaceContext` 在共享 Blade 布局中生成用户、范围摘要、模块和导航，写入 `data-workspace`，由 Vue 根组件向页面提供。前端不自行推断角色权限。
- 首页采用身份区、分组卡片；登录后 PC 顶部导航与手机底部导航按能力显示。游客显示登录入口，停用或无权限人员显示状态。管理导航定位首页管理模块，学生详情与毕业生归入学生导航。
- 路径与原请求参数保留；无新增数据库表或迁移。角色变更后的页面入口在刷新后更新，后端在请求时重新判断权限。

**行为变化：**辅导员默认可看本分院全部学生，包含非带班学生。原有按带班关系限制查看的测试已更新。辅导员默认不再访问导入和同步等管理员模块。
